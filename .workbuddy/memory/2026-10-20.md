## 音乐模块「打开项目后列表为空」定位与修复（0.4.0）

**现象**：打开/切换项目后，音乐模块不显示已导入音频；再导入一次后，历史音频一起出现。

**定位手段**：起一个临时诊断组件（已删）在运行中的 dev 实例里真调一次
`list_audios_with_meta`，写盘结果 → `{ok:true,count:4}`（谈完这个就去死，4 首）。
**结论：后端与项目状态正常，空列表来自前端**——两处叠加：
1. `PlayerView` 的 `useEffect(() => refresh(), [])` 只在挂载时拉一次；而 `Workspace`
   切项目时不卸载它（`key={activeModule}`，projectPath 连续变化），列表永久停留在上一个项目的快照；
2. `catch { setItems([]) }` 把失败吞成「还没有音频」，掩盖真实原因。
「导入」是当时**唯一**会再次调用 `ipc.listAudiosWithMeta()` 的路径 → 于是表现为「导入后才出现」。

**修复**：
- `PlayerView`：`refresh` 改 `useCallback`；effect 依赖 `[projectPath, refresh]`，切换时重置
  分组/搜索/时长并重拉；新增错误态（红条 + 重试）与工具栏「刷新」（应用外改文件后手动重扫）。
- `openProjectAt`：打开成功后 `clearAssetCache()` + `clearDurationCache()` +
  `bindPlayerToProject(path)`。
- `audioPlayer`：新增 `bindPlayerToProject` 与持久化字段 `playerQueueProject`；换项目丢弃旧队列
  （队列存相对路径，跨项目会指向同名文件）。`TopBar` 关闭项目时 bind(null)。
- `AppShell`：`installPlayerHotkeys()/restorePlayer()` 从渲染体移进 `useEffect(..., [])`
  （原先每次重渲染都重建 audio.src，打开命令面板/设置会打断播放）。
- `audioPlayer`：crossfade 分支 `nu.loop` 跟随 `loopOne`；末尾预触发在 `loopOne` 下不生效
  （原会把「单曲循环」变成「切下一首」）。
- `useSceneAudio`：`audio.loop = true`。原读 `settings.playerLoop`，但 P0 换成 playMode 后
  该设置已无写入点（恒 false）→ VN 的 BGM 播完即静音。
- Rust `assets.rs`：`ALLOWED_AUDIO_EXT` 提为模块常量，`list_audios` 与 `import_audio` 共用
  白名单（原先列表不过滤，手工丢进 assets/audio 的 jpg/txt 会被列成音频）。
- 新增 2 个 Rust 单测：缺目录返回空、非音频不列入；ref_count 统计剧本引用。

验证：`tsc` 干净；`vitest` 193 例；`cargo test --lib` 40 例；`vite build` 通过。
遗留未修（已在回答里列为建议）：`list_images` 同样无扩展名白名单、`playerCollections` 无项目维度、
`list_audios_with_meta` 每次全量读剧本、`advance()` 改下标不 notify、删当前曲目会清空整队列。
