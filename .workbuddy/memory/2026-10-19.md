## Anvil 缺陷审计（应「还有什么缺陷」之问，仅分析产出，未改代码）

### A. 引用完整性缺失（架构级，最硬）
`store/cards.rs::delete_card` 只清理卡组引用 + 文档，**不清理引用方的悬空边**：
- 棋盘 `token.card_id`（BoardCanvas:136 查不到 → BoardToken 退化成灰占位块 PlaceholderToken）
- 会话 `token.card_id`
- 卡盒 `pile.remaining / initial`
- 关系边 `from / to`（delete_relation 也只删 from 侧 + 索引，不删反向）

同类问题贯穿：`delete_board` 不管会话 `board_id`；`delete_card_group` 不管棋盘卡盒 `pile.group_id`；
`delete_card_type` 完全不管还在用该类型的卡。
**根因**：「一切实体皆卡牌」只建了正向引用，反向没有兜底。

### B. 撤销是动作级，不是数据级
`hooks/useDeleteUndo.ts` 的 restore 只 `saveCard(card)`，不恢复卡组身份 / 文档 / 关系。
而 UI 明确提示「可用 Ctrl+Z 撤销」（CardEditor.tsx:43）—— 提示与实际不符。
undo 栈纯内存、上限 100（undoSlice slice(-100)）。

### C. 性能
`useSessionEvents.logEvent` 每次 append 后 `reload()` 全量重读 events.jsonl；
`ChatLog` 无虚拟化（`shown.map` 全量渲染）→ 长会话 O(n²)，且无归档/分片。

### D. 结构
`story/script/ScriptEditor.tsx` 1036 行上帝组件（story/script 目录共 5670 行，占前端 7496 的 3/4）；
`store/export_html.rs` 1228 行。

### E. 检索
有 SQLite FTS + `needs_rebuild` 自愈（project.rs:50，这块是对的），
但 `useGlobalCommands` 命令面板无「搜卡并跳转」入口 —— 基础设施在，入口缺失。

### F. 数据可靠性
`store/atomic.rs::write_atomic` 只 fsync 文件、rename 后**不 fsync 父目录**；
tmp 用 `with_extension("tmp")` 且失败时不清理残留。

### G. 残留
`src-tauri/src/core/eval/` 空目录（CHANGELOG 说 eval 模块已删）。

### 建议优先级
A（引用完整性）> B（撤销语义）> C（长会话性能）> E（全局检索）> D/F。
A 修法：删除前先做引用扫描，给用户「还有 N 处引用」的确认 + 提供「一并清理 / 转为占位」选项。

### 五个关键设计决定（都不是显而易见的）
1. **不静默级联删除**。删一张卡悄悄清空半个棋盘比留悬空边更糟 —— 用户无从察觉。
   所以扫描结果交给用户三选一：移除引用者 / 保留引用者（detach）/ 取消。
2. **卡盒是容器不是引用者**。卡盒里少一张牌，卡盒本体要留着，`total` 跟着 `initial` 走，
   否则余量与实抽不符。
3. **先摘引用再删本体**。顺序反了就取不到卡名，detach 也就留不下
   `name_override = "红龙（已删除）"` 的墓碑。
4. **detach 才有墓碑，先攻条目两种力度都移除**（先攻条目没有占位形态，
   留着只指向空；移除后 turn_index 要夹回合法范围，空了就停掉战斗追踪）。
5. **删完必须整体重载 store**（`core/actions/reloadIntoStore.ts`）。
   后端连带改了棋盘/会话/关系/卡组，前端只删卡片本身会导致界面与磁盘不一致 ——
   用户在棋盘上再动一下，又把悬空 token 写回去。

### 老项目体检
命令面板「清理悬空引用」：扫全项目指向不存在卡牌的引用，先报数量、确认后一次性拔除。
不可逆，故放命令面板而非自动执行。

### 明确没做（诚实记录）
- **剧本文本引用不扫描**：0.4 的 weave 用 `@scene`/`@actor` 后跟**卡名**（非卡 id）引用，
  按名字做文本匹配误报率极高（`@scene 深岩矿坑` 未必是卡），提示噪声比缺失更糟。
  等剧本改用 id 引用或提供引用注解后再接入。
- **撤销仍只还原卡本身**（缺陷 B 未修）：undo 栈是动作级的，restore 只 `saveCard`。
  在三选一对话框里明说「Ctrl+Z 只还原卡牌本身」，不承诺兑现不了的事。

### 过程中修掉的两个真实缺陷（测试暴露）
1. 批量扫描卡盒时用 `.find()` 只报第一张 → 卡盒里有多张待删卡时会漏报。改为遍历+去重。
2. 卡盒 total 不跟着 initial 更新 → 余量与实抽不符。

## 撤销语义（缺陷 B）修完

**根因**：撤销栈机制（LIFO / 100 条）本身没问题，缺陷全在调用方的 restore 写成
「动作级」——把动作前的整个实体写回去。只要用户在撤销前又动了同一实体，
后来的编辑就被旧快照吞掉。

**核心原语 `src/lib/undoMerge.ts`**（纯函数，17 用例）：
- `mergeListById(before, after, current)`：列表按 id 对齐。本次删掉的按**原索引**
  插回；改过而用户没再动的回滚；用户之后又改了的保留；用户后加的保留。
  redo 时把 before/after 对调即语义对称。
- `mergeEntity(before, after, current)`：实体按键合并，只遍历本次改过的键；
  嵌套普通对象递归（grid 改 visible 不吞掉之后改的 snap）；带 id 的列表走上面；
  无 id 数组（先攻条目）按整体值。
- 判据只有一条：**当前值仍处于动作完成那一刻的状态才回滚，否则保留用户版本。**

**`src/core/actions/entityUndo.ts`**（22 用例）：删除前采集关系网足迹，撤销时按
id 与当前状态合并。detach 的墓碑名用后缀 `（已删除）` 判断用户是否改过名字；
先攻 turn_index 只在「当前值正好等于后端夹出来的结果」时才还原；
牌堆只插回 before 里有的牌（当时已抽走的不插）。

**修掉的静默失败**：TokenInspector 的 restore 调 `onSave(token)`，而 onSave 按 id
替换，棋子已不在列表 → 恢复完全无效。改为 Inspector 持有上下文、按 id 合并插回。

**`useDraft` 加 `resolveCurrent` 选项**：编辑器自动保存的撤销原来也整体写回，
五个编辑器（卡牌/卡组/卡类型/关系类型/剧情）接上后只回滚本次改过的键。

**纪律**：撤销回调里读状态一律 `useProjectStore.getState()` 现取 ——
getState() 返回的是那一刻的快照，提到闭包外面会拿到旧数组（我自己先犯了这个错）。

**删除的孤儿文件**：`src/core/actions/entityRefSnapshot.ts`（472 行，A 轮的初稿，
零引用，被 entityUndo.ts 取代）已删。

### 验证
tsc 0 错误；vitest 139 全过（新增 39）；cargo test --lib 25 全过；vite build 成功。

## 长会话 O(n²)（缺陷 C）修完

三条成本线，各自处理：

**读（后端）**：`append_event` 为算 `max(seq)+1` 全量读+全量解析整个
events.jsonl。改为 `last_seq()` 读**尾行**（JSONL 只追加不改写，尾行即最大 seq），
窗口 64KB，尾行解析失败 / seq 为 0 时退回全量扫描。

**传（前后端）**：`append_event` / `reveal_event` 改为返回落库的那条事件
（含 seq），前端 `useSessionEvents` 本地 append，不再整表重读。
整表重载只留给切会话与编辑/删除。

**渲染**：`ChatLog` 限额渲染（首屏 300 + 「加载更早」按锚点前插补 scrollTop）。
没引虚拟列表库——消息高度差异极大，估算高度会错位。卡表建一次 Map，
`ChatMessage` 加 memo + 调用方回调 useCallback 稳住身份。
gm 全景下过滤是恒等映射，直接复用 events 引用（否则每条消息又过滤一遍整表）。

### 测试抓到的真 bug
上次写入崩一半时文件不以换行结尾，直接 `writeln!` 会让新事件和那半行
粘成同一行，两条都读不回来。已加尾字节检查，缺换行先补。
（`append_falls_back_to_full_scan_when_tail_line_is_corrupt` 这条用例暴露的。）

### write_atomic（数据安全）
三步原子写原先缺第三步：**fsync 父目录**。rename 改的是目录项，

unix 上补刷父目录；Windows NTFS 自带日志，无便宜便携接口，跳过（已注释说明）。

1. **写失败留残留 tmp**，而 `list_card_ids` 按 `file_stem` 照单全收 →

2. tmp 名 `<name>.tmp` → `<name>.<ext>.tmp`，免得被按扩展名过滤的加载器误当数据。

### E：命令面板接入卡牌全文检索
**原有做法**：`useGlobalCommands` 里每张卡注册一条 `open.card.<id>` 命令。
两个问题：一万张卡 = 一万条注册 + 一万次 notify（`register` 每次 notify，
打开项目瞬间全量重算一万遍），且 effect 依赖 cards 指纹，改一张卡名
就把全部命令注销重注册；而且只匹配卡名，FTS（cards_fts + docs_fts，
字段值 + 文档正文）完全没入口。

**改为结果源机制**（`lib/commands.ts` 的 `ResultSource`）：
- `commandRegistry.registerSource()/listSources()`，**不 notify** ——
  源不改变静态命令列表，notify 会让整个面板重算过滤。
- `cardResultSource.ts`：≥3 字符走 FTS（trigram 下限），<3 字符走本地名字过滤
  （与卡片墙一致），FTS 失败/零结果也退回本地。索引残留的已删 id 映射时滤掉。
- 排序（`paletteRanking.ts`，7 用例）：标签以 query 开头或关键词**等于** query
  的静态命令永远排最前（否则输入「撤销」会被提到「撤销」的卡牌挤掉），
  其余静态命令排动态结果之后。动态结果**不**按 query 二次过滤 ——
  命中可能来自正文，label 里没那个词。
- effect 依赖从 `[projectPath, cardsFingerprint]` 收到 `[projectPath]`。

**测试时自己写错的用例**：查询词「酒馆」只有 2 字符，走了本地分支而非 FTS 分支，
mock 的 searchCards 根本没被调用。改成 4 字符查询词。

## 交互反馈与动效层（用户拍板：不做关系图谱，其余全做）

### 三条硬约束（写进 DESIGN §25，后面加动效都得过这三条）
1. **只动合成属性** transform / opacity / box-shadow；改 width / top / left 的一律不做。
2. **每条动效都要有无障碍退路**。CSS 里的走 `prefers-reduced-motion` 媒体查询，
   inline style 里的（媒体查询盖不住）走 `useReducedMotion` hook。两套并存不混用。
3. **先限额，再动效**。逐元素动效的成本 = 单卡成本 × 渲染数量，基数不受控就是 N 倍开销。

### 落地项
- 棋盘：`useTokenDrag` 暴露 snapped 坐标 → `dragPreview` 虚线落点预览；
  `useCanvasZoom` 改 rAF 插值（滚轮不跳，锚点固定在光标下）。
- 卡片墙：先 `RENDER_LIMIT = 240` 限额 + 「加载更多」（与 ChatLog 同源的锚点前插补
  scrollTop），再上 `useCardWallFlip`（FLIP，4 用例）。
- 卡牌：翻牌 `rotateY(180deg)` + preserve-3d（**过渡期间才挂双面**，静止只渲染当前面）；
  抽牌从卡盒 rect 起飞的 FLIP 飞入。
- 箔样倾斜：`useCardTilt` 挂 document 做**事件委托**（几百张卡不能各挂一个
  pointermove），只给 hover 那张写 CSS 变量。
- HP 条：`scaleX` + 数字 `useCountUp`，两者共用同一个插值值。
- 模块切换 `.module-enter` 140ms 淡入（只入场不退场）。

### 过程中修掉的三个真问题
1. **翻牌动画被自己吃掉**：`transition` 写成 `flipping ? 有过渡 : none`。
   但 `flipped` 与 `transform` 是同一次提交里改的，这次提交才打开 transition，
   浏览器看到的起点就是终点 → 动画直接没有。改为**过渡常挂**，
   `flipping` 只用来决定是否同时渲染双面。
2. **飞入改的是 left/top**：每帧重排。改为外层常驻落点 + `translate(dx,dy)`
   叠加在 transform 上，位移 = 起点 - 落点。
3. **BoardCanvas 的 O(T·C)**：每个 token 各自线性扫 `cards` / `cardTypes`，
   拖拽时每帧都在跑。改为进组件各建一次 Map（依赖 cards / cardTypes）。
   顺带把 `RelationLines` 循环里的 `relationKinds.find` 也换成 Map（O(R·K) → O(R+K)）。
   另：`FLIP` 里原先是「先量再清再量」，等于 2N 次强制布局，改为「先清再量」= N 次；
   闪卡倾斜的 rect 也从每次 pointermove 移到 rAF 里（一帧最多测一次）。
   另：token 的 drop-shadow 原来常驻，改成只在拖拽时挂 —— 几十个 token 就是几十个
   额外的滤镜渲染层；选中态交给 outline。

## 跑团模块前端布局改造（用户嫌「棋盘占大部分 + 底部对话拖拽观感差」）

**目标**：参考 Foundry/Discord 把对话升为全高侧栏列，废掉手搓拖拽，队伍面板可折叠。

**关键环境事实**：沙箱**无法访问 npm registry**，`pnpm add react-resizable-panels` 卡死（9 分钟超时）。改为零依赖自研分隔器。

### 改动
- `SessionEditor.tsx`：删 `chatHeight`/`resizingChat` 状态、`sessionContainerRef` 与手搓 mousemove 拖拽 effect；底部 strip + 顶部 `row-resize` 拖拽条替换为**水平 flex 三栏**（对话列 `flex:0 0 chatPct%` | 6px 分隔条 | 舞台 `flex:1`）。分隔条用 `onMouseDown` + window mousemove/mouseup 改 `flex-basis`，`localStorage("anvil-session-layout")` 持久化（范围 15–50%，默认 24%）。聊天可折叠为 28px 细条（⟨ 展开 / ⟩ 折叠）。
- `ChatPanel.tsx`：移除 `height`/`resizing`/`onResizeStart` 与顶部拖拽条，改为 `height:100%` flex 列（header + ChatLog `flex:1` + ChatInput）；头部加折叠按钮（接 `onCollapse`）。
- `SessionStage.tsx`：加 `partyCollapsed` 状态与折叠/展开；折叠时渲染 28px「队伍」竖条。
- `PartyPanel.tsx`：加 `onCollapse?` prop，头部加 ⟨ 折叠按钮。
- `index.css`：加 `.session-resize-handle`（悬停/拖拽 `.is-active` 金线高亮，无 transition）。

### 验证
tsc 0 错误；vite build 成功；vitest 175 全过。

### 取舍
原本想引 `react-resizable-panels`（VSCode 级手感），但联网受限；自研分隔器更轻、更贴合 Anvil「少依赖」取向，且天然零过渡、契合 reduced-motion。

## 检查器「不够灵敏」改造

**诊断**：不灵敏不是动效慢，而是**开合完全不跟选中状态联动** —— 唯一触发源是那个按钮。

### 改动
- 新增 `src/lib/inspectorPrefs.ts`（照 moduleOrder 套路）：width/collapsed 落
  localStorage，读时容错（脏数据/缺字段退回默认）、写时静默。
- `uiSlice` 从工厂函数`(set)=>({...})`改成`(set,get)=>{...return{...}}`：初值读偏好，
  `setInspectorWidth` / `setInspectorCollapsed` / `toggleInspector` 都写回
  （新增 `setInspectorCollapsed`，因为 toggle 是翻转，自动逻辑需要确定值）。
- `Inspector.tsx`：
  - `subjectKey = token?.id ?? edge?.id ?? card?.id ?? previewType?.id`。
    用「是谁」而非「有没有」，才能区分「换了一个」和「同一对象反复重渲染」。
  - `prevSubjectRef` 初值 `undefined`（未初始化）而非 `null` —— 用 null 的话首屏
    「无选中」会因为 prev===null 而不触发自动折叠。
  - `story`/`player` 不接管（检查器本身是常驻工作区）；切回受管模块时把 prev
    置 undefined 重新判断。
  - 面板主体抽成 `renderPanel(onCollapse, title)`，展开态与折叠预览共用一份内容。
  - **折叠态悬停预览必须是 absolute 浮层，不能进 flex 流**：把 28px 拉到 320px
    等于每帧挤压中间工作区，卡片墙/棋盘被迫重排。浮层是 28px 条的 DOM 后代，
    鼠标移上去不会触发 leave，所以不会闪。
  - 拖拽条 4→6px，`inspector-resize-handle` + `.is-active` 金线，双击重置 320。
- `useKeyboard.ts`：`Ctrl+I`（输入框内放行，那里是斜体；其余快捷键仍一律接管）。

### 一个生命周期坑
`peek` 状态在折叠/展开切换后会残留（例如折叠时先 hover 出预览再点按钮展开，
下次折叠会直接带着 peek 浮出来）→ 加 `useEffect(() => setPeek(false), [collapsed])`。

### 验证
tsc 0 错误；vitest 175 全过；vite build 成功。
